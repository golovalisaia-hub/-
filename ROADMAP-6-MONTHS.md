# Academy — маршрут с нуля: сначала тестировщик, затем Python

## Главный принцип

**Порядок выбран учеником:** сначала ручное тестирование (QA) с нуля, одновременно английский с нуля. Python начинаем **только после** того, как базовые навыки ручного QA подтверждены самостоятельными работами. Другие языки программирования — ещё позже, когда будет конкретная задача и основа Python. Не требуем Python для завершения начальных QA-уроков.

Шесть месяцев — ориентир для последовательного обучения, а не гарантия трудоустройства, свободного владения английским или освоения нескольких языков. Продвигаемся по результатам практики, а не только по календарю: можно выполнить несколько уроков за день и повторить сложные темы без штрафа.

## Этап 1: QA и English — вход с абсолютного нуля (ориентир: недели 1–4)

QA: что такое программа, требования, тестировщик и качество; интерфейс, ожидаемый и фактический результат; позитивные и негативные проверки; чек-листы, простые тест-кейсы и баг-репорты. Каждый день короткое объяснение, пример с разбором, упражнение и проверка понимания. Никакого обязательного Python.

English: звуки и чтение простых слов, базовая лексика, простые фразы и предложения, произношение и аудирование на доступном уровне. IT-слова добавляются постепенно и не заменяют общий английский. Повторение через интервалы и практика своими словами.

**Проверка этапа:** ученик самостоятельно объясняет разницу между ожидаемым и фактическим результатом, оформляет понятный чек-лист, пишет простой баг-репорт; на английском понимает и составляет несколько простых фраз в пределах пройденного материала.

## Этап 2: ручное QA + English (ориентир: недели 5–8)

Техники тест-дизайна: классы эквивалентности, границы, переходы состояний; жизненный цикл дефекта, приоритет/серьёзность, воспроизведение багов, тестовая документация. Практика на собственных сайтах и разрешённых учебных приложениях. Английский: базовая грамматика, короткое чтение, слух и письмо.

**Проверка этапа:** самостоятельные тест-кейсы с ожидаемыми результатами и корректно воспроизводимые баг-репорты; исправление недочётов после обратной связи.

## Этап 3: инструменты тестировщика + English (ориентир: недели 9–12)

DevTools, HTTP, API, JSON, Postman или аналогичный клиент, основы SQL для чтения учебных данных, Git как рабочий инструмент. Это инструменты QA, а не переход к изучению Python. Продолжаем английский с разговорными и техническими упражнениями.

**Проверка этапа:** безопасно проверить учебный API, объяснить запрос и ответ, написать несколько SQL-запросов SELECT, оформить результаты проверки.

## Этап 4: самостоятельная QA-практика и портфолио + English (ориентир: недели 13–16)

Собрать небольшой проверяемый проект: требования, план тестирования, чек-лист, тест-кейсы, настоящие найденные дефекты (если есть), отчёт о регрессии и README. Тренировать объяснение решений и типовые вопросы начинающего тестировщика. Продолжать английский ежедневно небольшими порциями.

**Переход к Python только после контрольной:** без готовых ответов выполнить учебное тестовое задание, защитить выбор проверок и объяснить несколько примеров API/SQL; при пробелах — дополнительные QA-уроки и пересдача. Не обещаем работу или профессиональную квалификацию по одному тесту.

## Этап 5: Python с полного нуля + English (ориентир: недели 17–22, после контрольной QA)

Отдельная последовательность, не перемешанная с вводными QA-уроками: установка/редактор или браузерная консоль → print → переменные → строки/числа → ввод → условия → циклы → списки/словари → функции → обработка ошибок → маленькие программы. Темп индивидуальный, каждая тема требует упражнения и объяснения результата. Английский продолжается параллельно.

**Проверка этапа:** написать несколько собственных маленьких программ без копирования и объяснить, как они работают. Если QA занимает больше времени, Python переносится без «просроченных» уроков.

## Этап 6: Python-практика и мост к автоматизации (ориентир: недели 23–26 и далее)

Закрепить Python проектами, затем по мере готовности pytest, учебное API-тестирование и простые автотесты. Другие языки (например, JavaScript или Java) изучать только после этого и под выбранную цель; это не обязательная часть первых шести месяцев. English продолжается: чтение документации, понимание речи, письмо и разговор на текущем уровне.

## Как должен работать сайт — правило для следующей реализации

- Стартовый маршрут и главный экран: **QA + English**. Вводный Python не является третьим обязательным блоком.
- По окончании подтверждённого QA-этапа открывается самостоятельный маршрут **Python + English**, а QA остаётся доступен для повторения.
- Для каждого предмета самостоятельная проверка знаний, черновики и прогресс. Суммарная «галочка дня» не должна скрывать непроверенные навыки.
- В существующей реализации первые 84 урока и задачи в SEVER исторически объединяют QA, Python и English. **Они ещё не соответствуют этому новому маршруту.** Нельзя считать QA+English эквивалентом старой тройной задачи или автоматически закрывать её без выполнения Python. Пока схема задач не согласована, не подменять данные и не редактировать код SEVER.
- Уроки не привязаны жёстко к календарному дню: можно пройти несколько за один день, но факт выполнения и запланированная дата хранятся раздельно.

## Что уже реально готово и что остаётся

В репозитории есть 84 старых комбинированных урока, вводные пошаговые материалы, QA-практика, английские карточки и Python-консоль. Они не превращаются автоматически в правильный QA-first курс от изменения этого документа. Нужно отдельно изменить интерфейс, логику завершения, программу уроков, хранение раздельного прогресса и синхронизацию с календарём, затем проверить реальные сценарии. Не заявлять, что шестимесячная QA-first программа завершена, пока эти изменения не сделаны и не протестированы.

Книги: разъяснения и задания пишем своими словами. Ранее названные книги нельзя считать сверенными по главам, пока конкретные файлы и издания не изучены; полный текст книг не публикуем.

Приватность: сейчас исходники и статические материалы публичны; защищённый доступ к самому сайту нужно настроить отдельно. Личные учебные записи должны быть доступны только владельцу через проверку авторизации и RLS.

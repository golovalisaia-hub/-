# ИИ-наставник Academy — версия на проверку

Статус: изменения находятся в отдельной ветке. Пока пользователь не проверил PR, не сливать в `main` и не развёртывать новую серверную функцию в рабочем Supabase.

## Почему это не просто чат

- На сервере есть 32 оригинальные учебные рубрики: 14 QA, 14 English, 4 Python (столько Python-упражнений реально опубликовано в практикуме). Для каждой заданы цель, задача, наблюдаемые критерии и типичная ошибка. Идентификатор урока проверяется сервером; произвольный текст «критериев» из браузера больше не считается источником истины.
- `Объясни`: короткое объяснение и вопрос. `Подсказка`: направление без решения. `Дай задание`: новая задача на применение темы. `Разбери ответ`: только конкретные замечания по присланному тексту, без выдуманных наблюдений, формального балла или зачёта.
- В уроке кнопка «Разобрать мой текст с ИИ» переносит введённый ответ **только после нажатия** в поле наставника. На экране его можно отредактировать; расходный запрос отправляется только после второго отдельного нажатия «Отправить». Перенесённый текст удаляется из временного `sessionStorage` при получении.
- На странице видны упражнение и критерии. История чата ограничена шестью последними репликами текущего урока и не синхронизируется с другими устройствами. При переключении темы начинается отдельный диалог. Python ограничен четырьмя существующими заданиями, вместо ссылки на несуществующие уроки 5–7.

## Безопасность и границы

- Наставник использует отдельную функцию `academy-tutor`, требующую JWT и роль `owner`. Ключ OpenAI хранится только в секретах Supabase (`ACADEMY_OPENAI_API_KEY`), в браузере находится только публичный ключ Supabase. Нет доступа к записям SEVER, изменениям календаря, отметкам прогресса и автоматической выдаче сертификатов.
- SQL-функция квотирует максимум 5 запросов за 5 минут и 30 за последние 24 часа; ошибки API и пустые ответы не изображаются как успешный разбор. Запросы к OpenAI используют `store:false`, но это **не** обещание отсутствия каких-либо логов обработки у провайдера.
- Наставник не запускает Python и не наблюдает работу внешних приложений. Письменный английский не считается проверкой произношения или уровня A1. Письменная проверка ИИ может ошибаться, поэтому не становится объективной сертификацией.

## Порядок выпуска после проверки

1. Владелец убеждается, что **API billing** активен (подписка ChatGPT сама по себе его не заменяет) и добавляет ключ только через `Supabase → Edge Functions → Secrets` с именем `ACADEMY_OPENAI_API_KEY`. Не передавать ключ в GitHub, чат или скриншот.
2. После одобрения PR сначала обновить серверную Edge Function, включая `index.ts` и `rubrics.ts`, с включённой проверкой JWT. Затем обновить сайт из `main`. Нельзя публиковать только новую страницу без новой серверной версии.
3. Выполнить первый реальный запрос из авторизованной Academy. Подтвердить ответ и отдельно проверить отказ с неверным/отсутствующим ключом, ограничение квоты и отсутствие незапрошенного изменения облачного прогресса. До реального ответа **нельзя писать, что OpenAI работает**.

## Проверка педагогики вручную

- QA, урок 6: в ответе есть заголовок и слова «не работает», но нет среды, шагов и фактического результата. Ожидается конкретное замечание о недостающих полях, не фальшивый зачёт и не придуманный баг.
- Английский, урок 3: `You am ready.` Ожидается исправление `You are ready.` и короткий новый вопрос; никакой оценки произношения.
- Python, упражнение 1: код печатает очищенную строку, но не возвращает её. Ожидается пояснение про `return`, без заявления о фактическом запуске кода.
- Попросить подсказку: не выдавать готовое решение. Сменить предмет во время ожидаемого ответа: управление блокируется до завершения, история другой темы не смешивается. При сбое API черновик остаётся в поле ввода.

Технические проверки браузера используют заглушки аутентификации и API, поэтому не тратят деньги и не подтверждают доступность живой модели. Эти проверки дополняют, но не заменяют ручную приёмку на iPhone и реальный запрос после настройки ключа.
